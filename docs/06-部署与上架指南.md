## 一、三种交付形态

同一个 `app/` 目录有三种出路，区别只在**提醒能不能穿透应用被杀**：

| 形态 | 产物 | 适用场景 | 应用关闭后能提醒吗 |
|---|---|---|---|
| PWA（静态站点） | 一组静态文件 | 试用、演示、内部走查 | ✗（浏览器硬限制） |
| Android 包 | `.aab`（上架）/ `.apk`（分发） | 正式发布 | ✓ |
| iOS 包 | `.ipa` | 正式发布 | ✓ |

**这一点必须先想清楚**：如果只部署 PWA，产品最核心的承诺「到点一定提醒」是不成立的。
`app/README.md` 的「已知限制」里已经如实写明，不要在上架文案里回避。

## 二、PWA 部署（今天就能做）

### 2.1 部署内容

零构建，把 `app/` 下的运行时文件整体放上去即可：

```
index.html
css/style.css
js/scheduler.js  js/platform.js  js/store.js  js/reminder.js  js/app.js
sw.js
manifest.json
```

`app/tests/` 与 `app/README.md` **不要**部署。

### 2.2 硬性要求

| 要求 | 原因 |
|---|---|
| 必须 HTTPS | Service Worker 与通知权限都要求安全上下文（`localhost` 例外） |
| `sw.js` 返回 `application/javascript` 且**不要强缓存** | MIME 不符会导致 SW 注册失败；强缓存会锁死旧版本 |
| `manifest.json` 返回 `application/manifest+json` 或 `application/json` | 否则清单被忽略，无法安装为 PWA |
| **不要**给 `.js` / `.json` 做 SPA 兜底 | 兜底会返回 `index.html`，SW 因 MIME 不符注册失败——这正是本项目踩过的坑 |

> 项目把清单文件从 `manifest.webmanifest` 改名为 `manifest.json`，原因之一就是
> 部分静态托管按扩展名做白名单，`.webmanifest` 会被 404 掉。

### 2.3 nginx 参考配置

```nginx
server {
  listen 443 ssl;
  server_name med.example.com;
  root /var/www/mediontime;

  location = /sw.js {
    add_header Cache-Control "no-cache, no-store, must-revalidate";
    types { } default_type application/javascript;
  }
  location = /manifest.json {
    default_type application/manifest+json;
  }
  location / {
    try_files $uri $uri/ /index.html =404;
  }
}
```

### 2.4 部署后自检（4 条，都必要）

1. 直接打开站点，能在浏览器地址栏看到「安装」入口
2. DevTools → Application → Service Workers：状态为 **activated and is running**
3. Application → Manifest：无报错，图标与名称正常
4. 点击「今日」页的「我已服药」，刷新页面后记录仍在

第 2 条不通过时，先看 Console 有没有 MIME 相关报错——按 2.2 表格逐条核对。

> 第 2 条现在有自动化兜底：`node app/tests/browser-check.mjs --port <端口>`
> 的第 8 组会真实读取 `navigator.serviceWorker.getRegistrations()`，
> 断言注册数为 1、状态为 `activated`、且 `CacheStorage` 里 `mediontime-v3`
> 的清单 8 个资源一个没漏。**部署到新环境后先跑这一组**，比肉眼看 DevTools 可靠。

## 三、Android 打包与上架

### 3.1 构建

构建步骤、权限声明清单、两个必踩的坑（精确闹钟是应用内设置、`allowWhileIdle` 有 9 分钟节流）
已写在 **`native/README.md`**，此处不重复。最快路径：

```bash
cd native
npm install
npm run android:add      # 生成原生工程（一次）
npm run patch:android    # 补 6 条权限声明（幂等）
npm run sync             # app/ → www/ + cap sync
npm run run:android      # 连真机或模拟器直接跑
```

### 3.2 签名（待执行）

```bash
keytool -genkey -v -keystore mediontime.keystore \
  -alias mediontime -keyalg RSA -keysize 2048 -validity 10000
```

**keystore 文件与密码必须离线备份**。丢了就再也无法更新已上架的应用，只能重新发一个包。
推荐用 Play App Signing：上传密钥由 Google 托管，自己保留上传密钥。

### 3.3 Google Play 提交材料清单

| 材料 | 说明 |
|---|---|
| 应用图标 | 512×512 PNG |
| 特色图片 | 1024×500 |
| 手机截图 | 至少 2 张，建议 4 张（今日页、强提醒页、记录页、我的） |
| 短描述 / 完整描述 | 注意：**不得出现"治疗""诊断""替代医嘱"等表述** |
| 隐私政策 URL | 必需。因申请了精确闹钟与全屏意图，属敏感权限应用 |
| 数据安全表单 | 本项目**不收集、不上传任何数据** → 如实选「不收集」。不要因为"保险"而勾选收集项，勾错了反而是违规 |
| 内容分级 | 成人向，健康类 |
| 目标受众 | 18+ |

### 3.4 权限申报要点

| 权限 | Play Console 需要做的事 |
|---|---|
| `SCHEDULE_EXACT_ALARM` | 在「敏感权限声明」中说明用途为**用药提醒**（用户自定义时刻必须准点） |
| `USE_FULL_SCREEN_INTENT` | Android 14+ 需申报；说明用于锁屏全屏提醒，属健康提醒场景 |
| `POST_NOTIFICATIONS` | 运行时申请，需在文案里解释用途 |
| `USE_EXACT_ALARM` | **不要声明**。该权限 Google Play 只批给闹钟/日历类应用，用药提醒声明会被拒审 |

`native/scripts/patch-native.mjs` 已把这条约束写成测试断言（`native/tests/native.test.mjs`），
后人误加会被测试拦下。

### 3.5 上架前必做

- 真机跑完 `docs/03-测试用例清单.md` §5 的 4 项真机用例（D-01 杀进程、D-02 重启、D-03 精确闹钟被关、D-04 Doze）
- 至少覆盖 2 个厂商 ROM（如原生 Android + 小米/华为），国产 ROM 的后台策略差异很大
- 确认「设置 → 应用 → 药准时 → 闹钟和提醒」被关时，应用内的可靠性自检能如实报出

## 四、iOS 打包与上架

### 4.1 构建（待执行，需 macOS）

```bash
cd native
npm install
npm run ios:add      # 需要 Xcode ≥ 15
npm run sync
npm run open:ios
```

### 4.2 App Store Connect 材料

| 材料 | 说明 |
|---|---|
| 截图 | 6.7" 与 6.5" 各一套（必需），建议补 5.5" |
| App 隐私标签 | 选「不收集数据」。本项目所有数据只存本机，如实填写即可 |
| 隐私政策 URL | 必需 |
| 医疗免责 | 描述中必须写明「本应用不提供医疗建议，不能替代医生或药师的诊断与处方」 |
| 审核备注 | 主动说明这是**本地提醒工具**，不含诊断/用药决策功能，可显著降低审核摩擦 |

### 4.3 审核容易踩的点

- **健康类应用的表述**：Apple 审核指南对健康/医疗类应用（Physical Harm 相关条款）审查较严。
  只要出现"根据血压判断是否加药"这类描述就会被拒。本项目在设计上就不做剂量建议（BR-06），
  上架文案要保持一致，不要为了营销效果加戏。
- **最低功能性**：不能只是网页套壳。本项目有完整的记录、统计、导出、长者模式，
  但审核备注里应主动说明离线可用、有本地数据功能。
- **Critical Alerts（静音模式下响铃）**：需要向 Apple **单独申请 entitlement**，仅对健康/安全类
  场景批准。申请时需说明「用药提醒若被静音，用户可能漏服」。**未获批准前不要在代码里开启该能力**，
  否则构建会失败。

## 五、隐私政策与合规文案

### 5.1 应用内已实现

「我的 → 隐私政策 / 免责声明」两行现在是**真的能打开**的弹层（此前只有箭头没有处理函数），
正文内容与代码行为一致：所有数据仅存本机、权限逐条说明用途、可导出可清除。

上架仍需一个**独立可访问的网页版**隐私政策 URL。可直接沿用应用内文案，补充：

- 运营主体名称与联系方式
- 生效日期与版本历史
- 未成年人条款
- 政策变更通知方式

### 5.2 合规红线（第 10 章要求，必须守住）

| 红线 | 在代码/文案中的体现 |
|---|---|
| 不给医学建议 | 漏服补救只问"补服还是跳过"，从不建议剂量（BR-06） |
| 不判断剂量 | 修改剂量会二次确认并提示"请核对医嘱"，但不做任何判断 |
| 明确免责 | 首启强制勾选免责声明，不可跳过 |
| 隐私默认最严 | **不出网**：默认没有服务器、一个请求都不发（relay 全为空才有数据流出去）；家属协同事件**恒定不含药名与剂量**（不是某个开关下的选项，见 `08-家属协同服务端.md` §4.1）。<br>本机另有「隐藏药名」开关（默认**关闭**，即本机通知默认显示药名），它只影响**本机屏幕**上的显示，与"数据是否出网"是两件事 |
| 数据可带走 | 一键导出 JSON，一键清除本地数据 |

> 医疗合规文案建议正式发布前由执业医师或专业法务复核。AI 产出的合规文案**不构成法律意见**。

## 六、发版流程（每次改代码都走一遍）

```bash
# 1. 全量回归（10 套，993 项）
node app/tests/scheduler.test.cjs
node app/tests/platform.test.cjs
node app/tests/smoke.test.cjs
node app/tests/pwa.test.cjs
node app/tests/a11y.test.cjs
node native/tests/native.test.mjs
(cd server && npm test)                       # 家属协同中继（会自己起一个临时服务）
python -m http.server 8788 --bind 127.0.0.1   # 另开终端
node app/tests/browser-check.mjs --port 8788
node app/tests/a11y-tree.mjs --port 8788      # 真实可访问性树（改了 aria/焦点/弹层时必跑）
node app/tools/ui-shots.mjs --port 8788       # 顺便刷新 docs/ui/ 的 UI 稿

# 2. 同步到原生工程
cd native && npm run www:check && npm run sync

# 3. 递增版本号后构建
```

版本号规则：语义化版本 `MAJOR.MINOR.PATCH`；
Android `versionCode` 必须单调递增，`versionName` 可用语义化版本。

> 第 1 步里的 `ui-shots.mjs` 不是可选项：它既断言 12 个关键页面真的渲染出来了，
> 又刷新 `docs/ui/` 里随仓库一起交付的 UI 稿。
> **每次发版顺手跑一遍，图就不会与代码脱节**——这正是交付物 #4 此前的问题
> （截图只存在于临时目录，换台机器就没了）。

> 第 3 步之后建议再做一次**省电回归**：原生容器里提醒轮询的唤醒次数应与 Web 一致
> （自适应唤醒：临近事件 30 秒 / 空闲 5 分钟上限）。
> 但要注意——**原生下真正的耗电大头不是这个轮询，而是系统闹钟本身与常驻通知**，
> 轮询优化主要影响应用在前台或后台存活时的开销。本轮未做真机功耗实测。
