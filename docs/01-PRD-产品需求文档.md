- 版本：v1.0
- 日期：2026-10-10
- 项目代号：MediOnTime / 药准时
- 阶段：P0 需求与原型

---

## 1. 产品定义

### 1.1 一句话定位
面向**长期服药人群及其家属**的用药提醒与依从性管理工具，核心价值是**让该吃的药一次都不落下**。

### 1.2 北极星指标
**周按时服药率**（Week On-Time Rate）= 一周内 `status = on_time` 的记录数 ÷ 应服药总次数。

辅助指标：
| 指标 | 定义 | 目标 |
|---|---|---|
| 提醒送达率 | 已触发提醒数 ÷ 应触发提醒数 | ≥ 99.9% |
| 提醒响应率 | L1 阶段被确认的比例 | ≥ 70% |
| 次周留存 | 第 2 周仍在使用 | ≥ 45% |
| 卡片完成率 | 有 ≥3 种药的用户中，完成建档的比例 | ≥ 60% |

### 1.3 产品原则
| 原则 | 落地要求 |
|---|---|
| 提醒必达 | 未确认必须逐级升级，禁止静默失败 |
| 极简操作 | 长者模式下确认服药 ≤ 1 次点击 |
| 不替代医生 | 只提醒、只记录，不输出剂量建议 |
| 隐私底线 | 用药数据本地加密，支持隐藏药名 |
| 离线可用 | 断网时全部核心功能可用 |

## 2. 用户与场景

### 2.1 用户画像

**P0 核心用户**

| 画像 | 年龄 | 关键特征 | 核心诉求 | 使用频率 |
|---|---|---|---|---|
| A 慢病中老年患者 | 55–80 | 高血压/糖尿病/心脏病，长期服 2–5 种药，视力与记忆力下降 | 字大、操作简单、提醒响得久 | 每日 2–3 次 |
| B 多重用药共病患者 | 60+ | 同时服 5 种以上，含餐前餐后区分 | 分时段精确排程、清单清晰 | 每日 4–8 次 |
| C 短期疗程服药者 | 25–60 | 术后/感染/激素疗程 3–14 天 | 疗程倒计时、自动结束 | 每日 3–4 次 |

**P1 次要用户**

| 画像 | 核心诉求 |
|---|---|
| D 家属 / 照护者 | 远程知晓服药情况、漏服告警、可代确认 |
| E 育龄/孕期女性 | 严格准点、隐私隐藏（通知不显示药名） |
| F 精神心理科患者 | 温和坚持、服药情绪记录 |
| G 异地出差/跨时区人群 | 时区自动换算、相对时间提醒 |

### 2.2 逐场景流程（对应提示词 S1–S8）

#### S1 · 长者听不到提醒（最高频场景）
```
07:00  系统触发 L1
        └─ 通知 + 提示音 + 短震动
07:05  未确认 → L2
        └─ 重复通知 + 音量提升 + 长震动（间隔可配 5/10/15 分钟）
07:15  未确认 → L3
        └─ 全屏强提醒，持续响铃，需手动关闭
        └─ 按钮：[我已服药] [稍后提醒 10 分钟]
07:30  未确认 → L4
        └─ 推送通知给绑定家属，家属可一键拨号
09:00  超过服药窗口 → L5
        └─ 标记漏服 → 进入补救流程（见 S5）
```

#### S2 · 餐前药 + 吃饭时间不固定
- 计划锚点设为**相对时间**：`餐前 30 分钟`
- 用户可在首页手动记录"本次进餐时间"，排程据此滚动推进
- 未记录时，回退到用户设定的默认用餐时间

#### S3 · 跨时区
```
检测到时区变化
  → 弹出选择：① 按当地时间服药（推荐）  ② 保持原服药节奏（每 8 小时）
  → 选择后重算未来 90 天排程
  → 提示："附近 3 次提醒时间已调整"
```

#### S5 · 漏服补救
```
判定：实际时间 - 计划时间 > 服药窗口（默认 120 分钟）
触发补救询问：
  ├─ 距下次服药 > 安全间隔 → "是否现在补服？"  [补服] [跳过]
  └─ 距下次服药 ≤ 安全间隔 → "已接近下次服药时间，建议跳过本次，请遵医嘱"  [知道了]
补服后：
  → 生成独立 intake_log（is_makeup = true, status = 'makeup'）
  → 原漏服记录保留，不覆盖
  → 显示免责文案："本应用不提供任何医疗建议，请遵医嘱"
```

#### S7 · 长者无障碍操作
- 首页卡片上的「我已服药」按钮 ≥ 88×88 px
- 长按或语音"吃药了"也可完成打卡
- 打卡成功给出高对比视觉反馈 + 震动 + 语音确认

## 4. 关键业务规则（硬约束）

| 编号 | 规则 | 实现要求 |
|---|---|---|
| BR-01 | 提醒不可静默失败 | 每次提醒未确认必须进入升级流程 |
| BR-02 | 历史不可篡改 | 修改处方只影响未来排程；历史记录只允许补录/标注 |
| BR-03 | 安全间隔优先 | 补服建议必须以"距下次服药时间"为约束 |
| BR-04 | 不下医学结论 | 所有补服/间隔/冲突提示统一表述"请遵医嘱" |
| BR-05 | 时区处理 | 以用户当前时区本地时间存储与计算 |
| BR-06 | 重启恢复 | 重启/更新/改时间后重建全部待触发提醒 |
| BR-07 | 权限降级提示 | 拒绝通知权限必须显式告知"提醒将无法工作" |
| BR-08 | 二次确认 | 删除计划、关闭全部提醒、修改剂量需二次确认 |
| BR-09 | 提醒上限保护 | 单日提醒数 > 20 时提示用户确认 |
| BR-10 | 状态判定阈值 | on_time ≤ 30min；delayed ≤ 窗口；否则 missed |

## 6. 交互流程图

### 6.1 首次使用
```
启动 → 免责声明（必须勾选）→ 通知权限申请
  ├─ 授权 → 身份选择（本人 / 家属）→ 添加第一个药品 → 今日页
  └─ 拒绝 → 显式警告"提醒将无法工作" → 引导系统设置 → 仍可进入（功能受限）
```

### 6.2 日常打卡
```
提醒触发 → 用户点击"我已服药"
  → 计算 delay = now - scheduled_at
  → 判定 status
  → 写入 intake_log
  → 取消该计划本次的后续待触发提醒
  → 首页进度 +1，给出视觉/震动反馈
```

### 6.3 修改处方
```
编辑药品/计划 → 二次确认弹窗（"修改后仅影响未来的提醒，历史记录不会被改写"）
  → 保存
  → 取消该计划所有 pending 提醒
  → 从当前时间起重新生成排程
  → 重建本地调度
```

## 7. 非功能需求

| 维度 | 要求 |
|---|---|
| 可靠性 | 提醒准时率 ≥ 99.9%，本地调度不依赖网络 |
| 性能 | 冷启动 < 2s；今日页渲染 < 300ms |
| 省电 | 无长驻后台服务；单日耗电 < 3% |
| 离线 | 核心功能全离线可用 |
| 无障碍 | 字号联动系统、长者模式 ≥ 24sp、高对比、屏幕朗读、状态不只用颜色区分 |
| 安全 | 本地数据加密、传输 TLS、一键删除全部数据 |
| 兼容 | iOS 15+ / Android 9+ / 主流浏览器 |

## 8. 合规要求

1. 不得宣称医疗功效，定位为**健康管理辅助工具**
2. 不做医学判断，统一表述"请遵医嘱/请咨询医生或药师"
3. 健康数据属**敏感个人信息**，须单独同意、明示用途、提供撤回途径
4. 首启免责声明（强制勾选）：
   > 本应用仅用于提醒与记录用药时间，不提供任何医疗建议，不能替代医生或药师的诊断与处方。请严格遵照医嘱服药。
5. 权限最小化，逐项说明用途后再申请
6. 上架材料：软著、隐私政策链接、权限说明清单、iOS 隐私清单
